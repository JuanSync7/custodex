# Slice SP-01 — `spmirror.py`: govern a mirrored SharePoint library

Custodex sees SharePoint documents and understands when they changed — by
mirroring the library into the repo tree as DETERMINISTIC TEXT and letting the
unchanged engine do everything else (fingerprint, doc↔doc edges, staleness,
ownership). Pinned contract: `ARCHITECTURE.md` §EPIC SP.

The deployed reality this slots into: `rag-sharepoint-api` (ai03.atlas) already
holds the cert-authenticated Graph client + a FastAPI proxy, and
`pull_sharepoint.py` already mirrors raw library bytes to local disk with a
size+last_modified manifest. SP-01 adds the GOVERNANCE half: convert raw
library files to stable text inside the repo, preserve engine baselines across
re-syncs, and report what changed. The Azure AD app registration EXISTS
(config.json on the service); nothing here needs new credentials.

## Goal (validable)

1. `Source` protocol with TWO impls: `DirSource` (a library already on disk —
   the `pull_sharepoint.py` output, and every offline fixture, K4) and
   `ProxySource` (the rag-sharepoint-api service over stdlib urllib,
   `include_content=true` base64 fetch); network/malformed failure = loud
   `SpMirrorError` (K8).
2. `Converter` protocol + built-ins `passthrough` (UTF-8, loud on undecodable)
   and `docx-text` (stdlib zipfile+ElementTree; paragraphs, Heading pStyle →
   `#`, numPr → `- `); CONTAINER-CHURN-INVARIANT: two docx zips with identical
   `word/document.xml` but different zip mtimes/member order convert to
   byte-identical text (a Word re-save with unchanged words never moves a
   hash). Unknown converter id in config = loud; a listed file with an
   unmapped suffix is SKIPPED and reported, never loud.
3. `SpMirrorConfig` from `config/spmirror.yaml` (settings.py file precedent) +
   `CDMON_SP_API` env override; include/exclude fnmatch globs + `max_bytes`.
4. `sync_mirror(cfg, repo_root, source, *, force, dry_run) -> SpSyncReport`:
   manifest skip (size+last_modified) → fetch → convert → write ONLY on body
   change (K7: second sync with no upstream change writes nothing), PRESERVING
   existing `cdm:` front matter byte-for-byte (the engine baseline survives
   every re-sync); manifest `.cdmon/sp-manifest.json` sorted-keys (K10),
   timestamps only ever copied from the source listing (never the clock);
   files gone upstream: manifest entry pruned, mirror file KEPT + reported as
   a `stale_candidate` (K5 — deletion is a human decision).
5. `cdx sp-sync [--config] [--repo-root] [--force] [--dry-run] [--json]`.
6. THE flagship e2e (offline, DirSource fixture): sp-sync → declare the
   mirrored doc in a config/cdmon unit with `depends_on` from a git-native
   doc → `monitor --apply` → `check` green → edit the upstream fixture file →
   sp-sync → `check` exit 1 with SUSPECT_LINK naming the edge → `resolve
   --edge` → green. This is the reason the epic exists.
